# 点云刷新性能验证

2026-09-05，Unity 2021.3.45f2，Windows，本机隔离工程 `.utmp/pointcloud-perf`。

## 问题与改动

原刷新流程在 Unity 主线程执行点云 JSON 解析、逐点对象转换、矩阵生成和高度色带列表扩容/复制。虽然请求方法标记为 async，后续 CPU 计算仍回到主线程。用户报告刷新卡顿；隔离测量确认这些阶段明显超过常见单帧预算。

改动局限于 `Assets/PointCloudLoader.cs`：

- 下载完成后取 byte[]，后台执行 UTF-8 解码和 JsonUtility 解析。字符串版 FromJson 支持后台调用，依据 [Unity 2021.3 文档](https://docs.unity.cn/cn/2021.3/ScriptReference/JsonUtility.FromJson.html)。
- 点数据使用值类型，减少逐点托管对象。
- 主线程快照构建参数，后台只计算数据；Mesh、Material 和绘制操作仍在主线程。
- 按色带计数后直接写入最终矩阵数组，移除临时矩阵列表；点只有平移和统一缩放，直接填矩阵。
- 每轮只写已退出绘制的缓冲，匹配长度的批次数组复用；当前画面保持只读。颜色、缩放或偏移调整也异步重建。
- 保留全部库区原始点数、坐标、颜色、刷新间隔和统一更新方式。没有修改用户的场景开关。

## 对比结果

使用同一份实际接口快照：7 个库区、35,442 点，矿球库为空。匹配主场景的 12 色带、0–6 高度范围、缩放 1、偏移 (-40, 1, -8)。同一 Unity 进程中分别预热 3 次、测量 20 次。

| 阶段 | 原实现中位耗时 | 优化后中位耗时 | 原最大耗时 | 优化后最大耗时 |
| --- | ---: | ---: | ---: | ---: |
| 解码、解析、转换、合并 | 63.961 ms | 42.694 ms | 67.838 ms | 44.741 ms |
| 高度色带批次构建 | 28.369 ms | 21.124 ms | 30.398 ms | 21.786 ms |

CPU 阶段总耗时约减少 31%；更主要的变化是大块计算已移出主线程。表中是隔离 CPU 基准，不是业务场景帧耗时；网络响应、主线程字节复制、GC 和 GPU 绘制仍有成本。当前 Unity Mono 的 GetAllocatedBytesForCurrentThread 返回 0，不能据此声称零分配。复用通过数组引用一致性验证。

## 回归结果

隔离 Unity 编译和回归通过。对照优化前代码逐个比较坐标、矩阵元素、颜色、批次长度与高度范围；检查空数据、1/1023/1024/35442 点、固定色/高度色、反向高度范围。后台解析和构建可正常执行。

本地 HTTP 服务回放真实响应，验证：先获取库区再请求全部 7 库、长 ID 不失真、重复刷新不重复发起请求、切换前旧缓冲不变、双缓冲复用、业务错误保留旧画面、失败后恢复、对象销毁后不发布新状态。日志中的一次 code=500 为测试主动注入的失败。

本地结果：`.utmp/pointcloud-perf/optimized.txt`。测试运行不加载业务场景、不连接 PLC。

## 业务场景复测步骤

1. 使用原场景参数、相同点数和相同刷新间隔，开启点云刷新；转动镜头并观察至少 10 次刷新。
2. Unity Profiler 查看 CPU Timeline 和 GC Alloc：刷新时解析与批次循环应位于工作线程；主线程不再出现原来的大块计算。
3. 切换高度着色、调整高度范围/缩放/偏移，确认旧画面保持到新结果完整就绪，颜色和位置最终正确。
4. 临时断开点云 API 后恢复，确认保持旧画面且能恢复刷新；刷新途中离开场景，检查无销毁后访问异常。

尚未在实际业务场景测量帧率、GPU 耗时或视觉画面；本次不声称完全消除了所有卡顿来源。
